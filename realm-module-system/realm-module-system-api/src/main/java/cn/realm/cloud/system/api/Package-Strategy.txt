realm-module-system-api/
└── src/main/java/cn/realm/cloud/system/api/
    │
    │  【包名】不带 server——server 是部署单元标识，api 是契约层标识。
    │  本模块与 realm-module-system-server 是两个 artifact，
    │  cn.realm.cloud.system.api.user 与 cn.realm.cloud.system.server.user
    │  语义上对应同一业务域的两个视角：远程契约与本地实现。
    │
    ├── common/                              # 远程契约的共享类型
    │   ├── PageResult.java                  # 分页结果（跨部署单元契约）
    │   │                                    # 与 server 的 shared/PageResult 同名同结构，
    │   │                                    # 靠包名区分：api.common.PageResult 用于
    │   │                                    # Feign 序列化，server.shared.PageResult 用于
    │   │                                    # 同进程 Modulith 模块间传递。
    │   │                                    # 字段名和类型必须稳定，变更需版本化。
    │   │
    │   └── enums/
    │       └── CommonStatusEnum.java        # 0-正常、1-停用
    │                                        # 只放"多个契约包共用"的枚举。
    │                                        # 某个枚举只在一个模块的契约里用，
    │                                        # 放该模块的 enums/，不放这里。
    │
    ├── user/                                # 用户模块远程契约
    │   │                                    # 同进程调用走 user 根包的 UserFacade；
    │   │                                    # 跨部署单元调用走本包的 UserApi。
    │   │                                    # 两套契约并存，不互相替代。
    │   │
    │   ├── UserApi.java                     # Feign 契约接口
    │   │                                    # 接口上写 @RequestMapping("/rpc-api/user")，
    │   │                                    # 方法上写 @GetMapping / @PostMapping 等。
    │   │                                    # 【不要】在接口上加 @FeignClient——
    │   │                                    # 那是消费方的注解，不是契约的一部分。
    │   │                                    # 消费方在自己模块的 internal/client 下
    │   │                                    # 定义 interface UserFeignClient extends UserApi。
    │   │
    │   ├── UserCreateRequest.java           # 创建用户请求
    │   │                                    # 只含远程调用方需要填的字段：
    │   │                                    # username、nickname、departmentId、status。
    │   │                                    # 【不要】包含 password——远程创建用户
    │   │                                    # 由服务端生成初始密码或走独立重置流程。
    │   │
    │   ├── UserUpdateRequest.java           # 更新用户请求
    │   │                                    # 【不要】包含 username——创建后不可变。
    │   │
    │   ├── UserPageRequest.java             # 分页查询请求
    │   │                                    # 字段：pageNo、pageSize、username、status。
    │   │                                    # 契约应先窄后宽：加字段比删字段容易，
    │   │                                    # 但加字段需要所有调用方同步升级，宁缺毋滥。
    │   │
    │   ├── UserResponse.java                # 用户响应
    │   │                                    # 字段：id、username、nickname、
    │   │                                    # departmentId、status。
    │   │                                    # 【不要】包含 password、salt、审计字段——
    │   │                                    # 字段越少，内部实现变更时需要通知的
    │   │                                    # 调用方越少。敏感字段（如 mobile）
    │   │                                    # 在服务端实现里脱敏，不靠消费方判断。
    │   │
    │   └── enums/
    │       └── UserStatusEnum.java          # 0-正常、1-停用
    │                                        # 与 CommonStatusEnum 的取舍：
    │                                        # 状态语义完全一致且不会独立演化，用 Common；
    │                                        # 用户状态未来可能扩展（锁定、注销），独立建。
    │
    ├── role/                                # 角色模块远程契约
    │   │                                    # 远程调用方通常只需要"查角色"用于权限判断，
    │   │                                    # 不需要创建、修改、删除——这些只由管理后台驱动。
    │   │
    │   ├── RoleApi.java                     # 角色远程契约接口
    │   │                                    # 典型方法：findById、listByIds、
    │   │                                    # existsByIds、findByCode。
    │   │
    │   ├── RoleResponse.java                # 角色响应
    │   │                                    # 字段：id、roleCode、roleName、
    │   │                                    # dataScope、status。
    │   │                                    # dataScope 是数据权限组件最常消费的字段。
    │   │
    │   └── enums/
    │       └── DataScopeEnum.java           # 1-全部、2-自定义、3-本部门、
    │                                        # 4-本部门及以下、5-仅本人
    │                                        # 被数据权限组件消费，放 api 而非 server，
    │                                        # 否则组件要依赖 server 的 jar。
    │
    ├── permission/                          # 权限模块远程契约
    │   │                                    # 核心职责：校验某用户是否拥有某权限码，
    │   │                                    # 几乎被所有业务服务调用。
    │   │
    │   ├── PermissionApi.java               # 权限远程契约接口
    │   │                                    # 典型方法：
    │   │                                    #   boolean hasPermission(Long userId, String code)
    │   │                                    #   List<String> listPermissionCodes(Long userId)
    │   │                                    # server 内部由 permission 模块编排
    │   │                                    # user → user_role → role_menu → menu 链路，
    │   │                                    # 远程调用方只看到"有没有权限"。
    │   │
    │   └── PermissionResponse.java          # 权限查询响应
    │                                        # 字段：boolean granted、List<String> codes。
    │                                        # hasPermission 直接返回 boolean，
    │                                        # 本类只服务于"批量查权限码"的场景。
    │                                        # 【不建】PermissionCheckRequest——
    │                                        # 只有 userId + code 两个参数，
    │                                        # 用 @RequestParam 传即可。
    │
    ├── menu/                                # 菜单模块远程契约
    │   │                                    # 典型消费方：报表服务需要菜单树做导航，
    │   │                                    # 网关需要权限码做路由校验。
    │   │
    │   ├── MenuApi.java                     # 菜单远程契约接口
    │   │                                    # 典型方法：findById、listByIds、
    │   │                                    # existsByIds、listByType。
    │   │                                    # 【不要】暴露写操作——菜单是低频变更的
    │   │                                    # 配置数据，只由管理后台维护。
    │   │
    │   ├── MenuResponse.java                # 菜单响应
    │   │                                    # 字段：id、parentId、menuName、
    │   │                                    # permissionCode、menuType、status。
    │   │                                    # 【不要】包含 ancestors——服务端树形操作的
    │   │                                    # 内部字段。调用方需要树，由服务端组装
    │   │                                    # children 返回，而不是让调用方解析祖先链。
    │   │
    │   └── enums/
    │       └── MenuTypeEnum.java            # 1-目录、2-菜单、3-按钮
    │                                        # 前端路由和权限校验共用。
    │
    ├── organization/                        # 组织架构模块远程契约（部门 + 岗位）
    │   │                                    # server 内部部门和岗位是同一 Modulith 模块，
    │   │                                    # api 层拆成两个契约接口——调用方通常
    │   │                                    # "要么只查部门、要么只查岗位"，
    │   │                                    # 合并会让调用方依赖它不需要的接口。
    │   │                                    # 接口拆分看消费方，模块划分看业务能力。
    │   │
    │   ├── DepartmentApi.java               # 部门远程契约接口
    │   │                                    # 典型方法：findById、listByIds、
    │   │                                    # existsDepartments、listAll（树形）。
    │   │
    │   ├── DepartmentResponse.java          # 部门响应
    │   │                                    # 字段：id、parentId、departmentName、
    │   │                                    # departmentCode、status。
    │   │                                    # 调用方需要树形结构时，由服务端组装
    │   │                                    # children 返回。
    │   │
    │   ├── PositionApi.java                 # 岗位远程契约接口
    │   │                                    # 典型方法：findById、listByIds、
    │   │                                    # existsPositions、page。
    │   │
    │   ├── PositionResponse.java            # 岗位响应
    │   │                                    # 字段：id、positionCode、positionName、status。
    │   │
    │   └── PositionPageRequest.java         # 岗位分页查询请求
    │                                        # 字段：pageNo、pageSize、positionName、status。
    │                                        # 部门没有分页 Request——部门是树形结构，
    │                                        # 调用方通常需要全量树，分页破坏结构。
    │
    ├── dict/                                # 字典模块远程契约
    │   │                                    # 字典几乎被所有业务服务调用——
    │   │                                    # "订单状态有哪些值""支付方式有哪些"
    │   │                                    # 这类查询都走字典模块。
    │   │
    │   ├── DictApi.java                     # 字典远程契约接口
    │   │                                    # 典型方法：
    │   │                                    #   DictTypeResponse findTypeByCode(String code)
    │   │                                    #   List<DictDataResponse> listDataByTypeCode(String code)
    │   │                                    # 两个方法的返回值类型不同，不合并成
    │   │                                    # "返回字典详情"的大对象——调用方通常
    │   │                                    # 只需要其中一部分。
    │   │
    │   ├── DictDataResponse.java            # 字典数据响应
    │   │                                    # 字段：id、dictTypeCode、dataLabel、
    │   │                                    # dataValue、sortOrder、status。
    │   │                                    # dataValue 统一为 String——即使业务上是
    │   │                                    # 数字，字典值也存字符串，由调用方按需转换，
    │   │                                    # 避免跨服务的类型歧义。
    │   │
    │   └── DictTypeResponse.java            # 字典类型响应
    │                                        # 字段：id、dictTypeCode、dictTypeName、status。
    │                                        # 调用方只按 code 查数据、不关心类型元信息时，
    │                                        # 本类可以不建。
    │
    └── setting/                             # 系统配置模块远程契约
        │                                    # 原 config，改名为 setting 以避免与
        │                                    # @Configuration、application.yaml 混淆。
        │
        ├── SettingApi.java                  # 系统配置远程契约接口
        │                                    # 典型方法：getByKey(String key)、
        │                                    # listByGroup(String group)。
        │                                    # 【不要】暴露写操作——配置只由管理后台维护。
        │
        └── SettingResponse.java             # 系统配置响应
                                             # 字段：id、settingKey、settingValue、group。
                                             # settingValue 统一为 String，
                                             # 调用方按业务需要自行转换类型。
